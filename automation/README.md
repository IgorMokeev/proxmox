# Автоматизация Proxmox VE: Cloud-Init шаблоны

Набор bash-скриптов для быстрого создания шаблонов виртуальных машин в Proxmox VE из официальных cloud-образов. Из готового шаблона ВМ клонируются за секунды, а в связке с Terraform (папка [`terraform-proxmox`](terraform-proxmox/README.md)) из шаблонов можно поднимать целые стенды.

Я тестировал на Proxmox > 9 версии.

| Скрипт | ОС | Версия |

Точные параметры каждого скрипта (ID шаблона, имя, образ, ресурсы) указаны в разделе `НАСТРОЙКИ` в начале файла и в его шапке-комментарии.

## Версии base и ext

| | base | ext |
|---|---|---|
| Хранилище дисков | только `local-lvm` | любое, на выбор |
| Хранилище snippets | только `local` | на выбор |
| Выбор формата диска (raw / qcow2) | не нужен | есть |
| Формат EFI-диска | не нужен (LVM-thin работает из коробки) | есть |
| Скорость | выше | на внешних хранилищах может быть заметно ниже |
| Сложность | минимальная | больше вопросов в интерактивном режиме |

**Правило выбора:** если у вас стандартная установка Proxmox с `local-lvm` — берите `base`. Если нужны внешние или нестандартные хранилища (NFS, Ceph, ZFS и т. п.) — берите `ext`. Если на сервере нет `local-lvm`, `base`-скрипт остановится на предварительных проверках и подскажет использовать `ext`.

## Как это работает

Все скрипты работают по одной схеме:

1. **Предварительные проверки (preflight).** Запуск от root, наличие SSH-ключей, формат хэша пароля, корректность введённых значений, наличие образа, свободный VM ID, доступность хранилищ и директории snippets.
2. **Создание vendor-snippet** — cloud-init файла для первого старта каждого клона (часовой пояс, установка `qemu-guest-agent` и т. д.).
3. **Создание ВМ:** `qm create`, EFI-диск (для UEFI), импорт cloud-образа, подключение диска, порядок загрузки, Cloud-Init диск, расширение диска.
4. **Настройка Cloud-Init:** пользователь, пароль (хэш), SSH-ключи, сеть (DHCP), ссылка на snippet.
5. **Конвертация в шаблон** (`qm template`).

Если скрипт упал после создания ВМ, он **автоматически удаляет недособранную ВМ**, чтобы повторный запуск не упирался в «VM уже существует».

## Подготовка

Пример для Ubuntu 24.04. Для остальных ОС набор шагов такой же, меняется только образ (см. шапку нужного скрипта).

**1. Скачайте cloud-образ в `/root` на сервере Proxmox и переименуйте в `.qcow2`:**

```bash
cd /root
wget https://cloud-images.ubuntu.com/noble/current/noble-server-cloudimg-amd64.img
mv noble-server-cloudimg-amd64.img noble-server-cloudimg-amd64.qcow2
```

**2. Подготовьте SSH-ключ.** Это обязательное условие: без публичного ключа в `/root/configs/authorized_keys` скрипт завершится с ошибкой.

```bash
ssh-keygen -t ed25519 -C "proxmox-template"       # если ключа ещё нет
mkdir -p /root/configs
cat ~/.ssh/id_ed25519.pub >> /root/configs/authorized_keys
chmod 600 /root/configs/authorized_keys
```

**3. (Для base) Убедитесь, что на хранилище `local` включён тип контента Snippets:**
Datacenter → Storage → `local` → Edit → Content → добавить **Snippets**.

**4. Сделайте скрипт исполняемым:**

```bash
chmod +x cloudinit_tmpl_ubuntu2404_base.sh
```

## Запуск

```bash
./cloudinit_tmpl_ubuntu2404_base.sh            # интерактивный режим (меню и вопросы)
./cloudinit_tmpl_ubuntu2404_base.sh --default  # автоматический режим, все параметры по умолчанию
```

В интерактивном режиме меню предлагает:

1. создать шаблон с настройками по умолчанию;
2. настроить параметры вручную (VM ID, имя, RAM, BIOS, пользователь, имя файла образа; `ENTER` = значение по умолчанию);
3. выйти.

## Настройки по умолчанию (на примере Ubuntu 24.04 base)

| Параметр | Значение |
|---|---|
| VM ID шаблона | `11243` |
| Имя шаблона | `ubuntu24cloud-tmpl` |
| Тег Proxmox | `cloud_tmpl` |
| RAM | 4096 МБ |
| Ядра CPU | 2 |
| Тип CPU | `x86-64-v2-AES` |
| Тип машины | `q35` |
| BIOS | `ovmf` (UEFI), можно `seabios` |
| Диск | образ + 5 ГБ |
| Хранилище дисков | `local-lvm` |
| Хранилище snippets | `local` |
| Сеть | `vmbr0`, firewall включён, DHCP |
| Часовой пояс | `Europe/Moscow` |
| Пользователь Cloud-Init | `la` |
| Автообновление при первом старте | выключено |
| Установка при первом старте | `qemu-guest-agent` |

Все значения собраны в разделе `НАСТРОЙКИ` в начале скрипта, их можно менять прямо там.

Тег `cloud_tmpl` ставится при создании ВМ и остаётся у шаблона. По нему удобно фильтровать шаблоны в веб-интерфейсе Proxmox.

## Пользователь и пароль

По умолчанию создаётся пользователь `la` (local admin) с **тестовым паролем из примера в скрипте**. Он годится для домашней лаборатории, но для любых других случаев его необходимо сменить.

Хэш пароля можно задать двумя способами.

**Способ 1: переменная в скрипте.** Сгенерируйте хэш и подставьте в `CI_PASS_HASH` (в **одинарных** кавычках, иначе bash раскроет символы `$`):

```bash
openssl passwd -6 'Ваш_Надёжный_Пароль'
```

```bash
CI_PASS_HASH='$6$...ваш_хэш...'
```

**Способ 2 (рекомендуется): файл.** Хэш не хранится в скрипте и не попадёт в репозиторий:

```bash
openssl passwd -6 'Ваш_Надёжный_Пароль' > /root/configs/cipass.hash
chmod 600 /root/configs/cipass.hash
```

Если файл `/root/configs/cipass.hash` существует и не пуст, он имеет приоритет над `CI_PASS_HASH`.

Вход по SSH выполняется ключом, публичная часть которого лежит в `/root/configs/authorized_keys`:

```bash
ssh -i ~/.ssh/id_ed25519 la@<IP>
```

## Что делать после создания шаблона

Клонирование и запуск:

```bash
qm clone <ID_ШАБЛОНА> <НОВЫЙ_ID> --name <hostname> --full
qm start <НОВЫЙ_ID>
```

Для шаблона Ubuntu по умолчанию:

```bash
qm clone 11243 5001 --name test-vm-01 --full
qm start 5001
```

Что получите в клоне: пользователя и SSH-ключи из шаблона, сеть по DHCP (её можно переопределить через `qm set <ID> --ipconfig0 ip=...`), установленный и запущенный `qemu-guest-agent` после первой загрузки.

## Связь с Terraform

Созданные здесь шаблоны используются как основа для Terraform-сценариев из папки [`terraform-proxmox`](terraform-proxmox/README.md): одна ВМ, несколько ВМ из разных шаблонов и стенд Kubernetes. В Terraform шаблоны указываются по ID, поэтому не меняйте ID шаблонов без необходимости или обновите значения в `terraform.tfvars`.

## Частые проблемы

| Симптом | Что делать |
|---|---|
| `SSH-ключи не найдены` | Создайте `/root/configs/authorized_keys` с публичным ключом (см. [Подготовка](#подготовка)) |
| `Образ не найден` | Скачайте образ в `/root` и переименуйте в `.qcow2`, либо укажите другое имя файла в интерактивном режиме |
| `VM ... уже существует` | Выберите другой VM ID или удалите старую ВМ: `qm destroy <ID> --purge` |
| `Хранилище 'local-lvm' не найдено` | На установках Proxmox с ZFS/ext4 `local-lvm` может не быть: используйте `ext`-версию |
| `Не включён тип контента Snippets` | Datacenter → Storage → `local` → Edit → Content → добавьте **Snippets** |
| `CI_PASS_HASH не похож на хэш SHA-512` | Хэш должен иметь вид `$6$salt$hash` и быть в одинарных кавычках |
| Не входит по SSH | Проверьте, что используете ключ, чья публичная часть лежит в `authorized_keys` на момент создания шаблона. Ключи «запекаются» в шаблон, при их смене шаблон нужно пересоздать |
| Нет данных гостя в Proxmox (IP, shutdown) | `qemu-guest-agent` ставится при первой загрузке клона и требует доступ в интернет: проверьте сеть, шлюз и DNS |
